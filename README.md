# Stokes with native deal.II PSCToolkit block algebra

This application preserves the original Stokes benchmarks and solver options
while using the native block matrix and block vector interfaces added to
deal.II. Select `PSBLAS`, `PETSc`, or `Trilinos` at run time among the backends
enabled in the linked deal.II build.

For PSBLAS, the matrices are `PSCToolkitWrappers::BlockSparseMatrix` and
`SparseMatrix`, and every Krylov vector is a `PSCToolkitWrappers::BlockVector`
or `Vector`. Finite element assembly and matrix/preconditioner applications
operate on that native storage. The previous distributed-vector conversion
layer and separate raw PSBLAS matrix implementation have been removed.

## Build against the modified deal.II library

Use the deal.II build or installation containing the native PSCToolkit block
patch, with MPI, p4est, PSBLAS, and AMG4PSBLAS enabled. Its PSBLAS and AMG4PSBLAS
dependencies must contain the native extensions used by that patch. PETSc and
Trilinos remain optional comparison backends.

```sh
cmake -S . -B build-stokes \
  -DDEAL_II_DIR=/absolute/path/to/modified/dealii-build \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build-stokes --target stokes --parallel 8
```

Use `-DCMAKE_BUILD_TYPE=Debug` if the selected deal.II build provides only its
Debug configuration.

The normal `deal_ii_setup_target(stokes)` setup supplies dependency information.
The application introduces no additional block-support switch or capability
probe. Keep `PSBLAS_DIR` and `AMG4PSBLAS_DIR` in the deal.II configuration, as
before.

Alternatively, use the location-independent helper:

```sh
DEAL_II_DIR=/absolute/path/to/modified/dealii-build \
  sh configure-laptop/build-stokes.sh
```

The original dependency submodule pins belong to the prototype. Point this
application to the newly modified deal.II library.

## Run the benchmarks

```sh
./build-stokes/stokes --help
mpiexec -n 4 ./build-stokes/stokes parameters/poiseuille.prm
mpiexec -n 4 ./build-stokes/stokes parameters/backward_step.prm
mpiexec -n 4 ./build-stokes/stokes parameters/cavity_regularized.prm
mpiexec -n 4 ./build-stokes/stokes parameters/cavity_leaky.prm
mpiexec -n 4 ./build-stokes/stokes parameters/cavity_watertight.prm
mpiexec -n 4 ./build-stokes/stokes parameters/colliding.prm
```

Each example has its own output directory. Running `stokes` without arguments
creates a fully documented `parameters.prm` and exits; an existing file is
preserved. Passing a missing filename also creates defaults and exits. Pass an
existing parameter file explicitly to solve.

Additional ready-to-run inputs are `parameters/poiseuille_minres.prm`,
`parameters/poiseuille_gmres.prm`, and `parameters/poiseuille_amg_options.prm`.
The last demonstrates a relative native-options file together with named and
typed AMG settings.

`parameters-template.prm` contains the full documented parameter inventory
generated by the validated executable. Copy it before customizing an experiment.

The equations, boundary conditions, pressure treatment, full parameter syntax,
and backend settings are documented in [README_STOKES.md](README_STOKES.md).
The discretization remains two-dimensional continuous Taylor–Hood
`[Q_(k+1)]^2/Q_k`, with selectable pressure degree, viscosity, refinement count,
and refinement cycles.

## Solver choices

All existing parameter names are retained:

- `Linear algebra/Backend`: `PSBLAS`, `PETSc`, or `Trilinos`.
- `Linear algebra/Block preconditioner`: `diagonal`, `upper triangular`, or
  `lower triangular`.
- `Linear algebra/LinearSolver/Method`: `MINRES`, `GMRES`, or `FGMRES`.
- Each of `Velocity block` and `Pressure block`: `Action = apply|solve`,
  `Solver = cg|gmres|fgmres`, and independent iteration limits and tolerances.
- Backend-native preconditioner settings: the full `AMG4PSBLAS` option
  catalogue, PETSc `pc_type` and private options, and Trilinos ML/Ifpack choices.

FGMRES supports tolerance-controlled auxiliary solves. GMRES requires a fixed
linear preconditioner. MINRES additionally requires symmetry and a positive
definite preconditioning action. These mathematical requirements remain
documented choices, without new restrictions on experiments.

## Output and verification

Each run records the effective parameters and a `summary.csv` containing mesh
sizes, iteration counts, the recomputed true residual, divergence, pressure
mean, boundary fluxes, timings, and analytic errors when available. Residual
histories and parallel VTU/PVTU output are independently selectable.

```sh
ctest --test-dir build-stokes --output-on-failure
```

The test suite covers exact solutions, solver and block choices, MPI operation,
the nonanalytic benchmarks, refinement, and native AMG settings.
